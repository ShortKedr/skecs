# Переход с SECS 0.1.0 на SKECS 0.2.0

При переходе на `ShortKedr.SKECS.0.2.0.nupkg` меняются имена
пакета, пространства имён, сборки и исходного проекта. Старые имена не являются
совместимыми псевдонимами. Проекты, остающиеся на SECS 0.1.0, должны использовать
исходный пакет и документацию к нему.

| SECS 0.1.0 | SKECS 0.2.0 |
| --- | --- |
| `ShortKedr.SECS` version `0.1.0` | `ShortKedr.SKECS` version `0.2.0` |
| `using SECS;` | `using SKECS;` |
| `SECS.World` | `SKECS.World` |
| `SECS.dll` | `SKECS.dll` |
| `SECS/SECS.csproj` | `SKECS/SKECS.csproj` |
| `SECS.sln` | `SKECS.sln` |

## Проверка автоматической миграции

Локальный [модуль `skecs-migration`](https://github.com/ShortKedr/skecs/tree/skecs-v0.2.0/skecs-migration) выполняет механическое
переименование пакета и пространства имён C#. Это нативный .NET CLI для SDK 8
или новее; при первой сборке `dotnet run` восстановит закреплённую зависимость Roslyn.
Используйте утилиту из исходников `skecs-v0.2.0`. Запускайте её из корня этой
копии репозитория, указав каталог **своего проекта-потребителя**. При
централизованном управлении пакетами включите в выбранный каталог файл
`Directory.Packages.props`. Сначала сохраните изменения в системе контроля
версий или резервной копии. Для анализа привязки сущностей по исходной сборке
скачайте `ShortKedr.SECS.0.1.0.nupkg` из
[релиза SECS 0.1.0](https://github.com/ShortKedr/skecs/releases/tag/secs-v0.1.0).

```powershell
dotnet run --project skecs-migration -- C:/Projects/MyGame --from 0.1.0 --to 0.2.0 --old-package "C:/packages/ShortKedr.SECS.0.1.0.nupkg"
```

По умолчанию скрипт показывает diff без записи файлов. Проверьте изменения,
особенно идентификаторы `SECS`, которые могут обозначать вашу переменную или
псевдоним. Для переименования CLI использует синтаксические деревья Roslyn.
Объявления и псевдонимы `SECS`, а также неактивные
ветки препроцессора с `SECS` останавливают предварительную проверку для ручного
разбора. Для применения проверенного преобразования:

```powershell
dotnet run --project skecs-migration -- C:/Projects/MyGame --from 0.1.0 --to 0.2.0 --old-package "C:/packages/ShortKedr.SECS.0.1.0.nupkg" --apply
```

CLI обновляет импорты пространства имён и явные обращения
`SECS.`/`global::SECS.` в файлах `.cs`. Он сохраняет комментарии, символьные
литералы и текст строк, включая дословные, необработанные и интерполированные строки.
Обращения к пространству имён внутри интерполированных выражений также обновляются. В `.csproj`,
`.props` и `.targets` скрипт изменяет точное имя `ShortKedr.SECS` в элементах
`PackageReference` и `PackageVersion`, заменяя буквальную версию `0.1.0` на
`0.2.0`. Ссылки без версии остаются без версии для централизованного управления
пакетами. Свойства MSBuild, диапазоны версий и другие версии старого пакета
останавливают выполнение до записи файлов: их нужно исправить вручную.
В файлах Unity `.asmdef` CLI заменяет точные вхождения `SECS.dll` в
`precompiledReferences`.

Параметр `--old-package` включает анализ дескрипторов по опубликованной сборке
SECS. Чтобы отметить вероятные места для ручной проверки, опустите параметр
в обеих командах.
Если Roslyn может определить мир-владелец в прямом цикле по чанкам
типизированного запроса, CLI заменит
`new Entity(chunk.Entities[row], chunk.Versions[row])` на
`world.BindEntity(chunk.Entities[row], chunk.Versions[row])`. Получателем
должна быть локальная переменная `using var`, доступная только для чтения.
Просмотрите оставшиеся вызовы конструктора, проверки `IsValid`, сравнение и
хеширование, отмеченные при анализе. Обработайте вручную косвенные запросы,
случаи с неоднозначным миром-владельцем и код с неразрешёнными ссылками.

В файлах UTF-8 и UTF-16 с BOM сохраняются кодировка, BOM и переводы строк.
Некорректный входной файл останавливает предварительную проверку. Генерируемые
каталоги и кеши, например `bin`, `obj`, Unity `Library`, `.godot`, `node_modules`
и `artifacts`, а также символические ссылки пропускаются. CLI не восстанавливает
пакеты потребителя, не собирает проекты, не переименовывает файлы, не импортирует DLL и не
обращается к удалённым сервисам. Повторный запуск после применения миграции
не создаёт новых изменений.

## Ручные шаги

1. Добавьте целевой `ShortKedr.SKECS.0.2.0.nupkg` в источник NuGet проекта,
   как описано в [руководстве по установке](INSTALL.ru.md). Проверьте централизованные свойства
   версий и версии пакетов вне выбранного каталога.
2. При подключении исходных проектов обновляйте пути проекта и решения только
   после появления исходников SKECS по новым путям. Скрипт не переименовывает
   каталог исходников и не изменяет файлы `.sln`.
3. В Unity удалите старую `SECS.dll` и импортируйте
   `lib/netstandard2.1/SKECS.dll` из `SKECS.Unity.0.2.0.zip`.
   Проверьте изменения в определениях сборок, настройки импортёра и фильтры платформ.
   Следуйте [инструкции для Unity](INSTALL.ru.md#unity).
4. Для Godot .NET (C#) восстановите новый пакет в C#-проекте и пересоберите
   сцену. Следуйте [инструкции для Godot .NET](INSTALL.ru.md#godot-net-c).
5. Проверьте строки рефлексии и имён сборок, метаданные сериализации, псевдонимы
   и неактивные ветки препроцессора. Их нельзя
   безопасно переименовать как произвольный текст. Пересоберите зависимые сборки
   с новым именем.

## Дескрипторы сущностей и время жизни мира

- Сохраняйте привязанный дескриптор, который вернул мир или получил обработчик
  запроса. При восстановлении дескриптора из сохранённых координат или
  из ID и поколения в чанке вызовите `owningWorld.BindEntity(id, version)`
  в мире, которому принадлежат координаты. `new Entity(id, version)`
  создаёт непривязанный дескриптор. `BindEntity` привязывает координаты без
  проверки существования сущности. Сохраняйте контекст мира отдельно от
  ID и поколения.
- Проверяйте существование сущности через `world.IsAlive(entity)`.
  `entity.IsValid` проверяет привязку и допустимость ID и поколения. Оно
  может оставаться истинным после удаления сущности или освобождения мира.
  Сравнение и хеширование учитывают мир. Пересмотрите ключи и кеши, которые
  считали равными одинаковые ID и поколения из разных миров.
- В рабочем мире `World.IsAlive`, `World.TryGet` и `Has`/`TryGet` аксессора
  компонента возвращают false для чужих, непривязанных и устаревших
  дескрипторов. Строгие операции, например `World.Has` и `World.Get`,
  выбрасывают для них `InvalidOperationException`.
- Освобождайте мир после завершения запроса, в том числе при раннем выходе.
  Вызов `Dispose` внутри `Query.ForEach` выбрасывает
  `InvalidOperationException`. После освобождения операции, которым нужен
  рабочий мир, выбрасывают `ObjectDisposedException`. Повторный `Dispose`
  безопасен.

## Проверка проекта-потребителя

После применения изменений повторите предварительный просмотр. Утилита не
должна предложить дополнительных правок. Восстановите пакеты и проверьте,
что проект использует `ShortKedr.SKECS` 0.2.0. Соберите проект и запустите его
тесты с конфигурацией источников пакетов проекта.

```powershell
dotnet restore C:/Projects/MyGame/MyGame.csproj
dotnet build C:/Projects/MyGame/MyGame.csproj -c Release --no-restore
dotnet test C:/Projects/MyGame/MyGame.csproj -c Release --no-restore
```

Для Unity отдельно проверьте Editor и каждый требуемый backend плеера. Для
Godot .NET запустите сцену в редакторе .NET. В самом проекте проверьте создание
мира, запросы, доступ к компонентам и освобождение ресурсов. Проверьте
изменённые сценарии работы с дескрипторами после удаления сущности или
повторной выдачи ID, а также в мирах с одинаковыми ID и поколениями.
