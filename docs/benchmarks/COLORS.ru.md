# Цветовая шкала отчётов о бенчмарках

[Карта документации](../README.ru.md) · [Результаты SECS](current/REPORT.ru.md) · [Результаты SpaceBattle](../space-battle/REPORT.ru.md)

Одинаковые цвета показывают относительные различия в сопоставимых таблицах и графиках. Основанием остаются напечатанные числа, единицы, погрешности и исходные данные; цвет помогает быстрее прочитать их.

## Что означают цвета

База — лучшее неокруглённое значение в явно сопоставимой группе. Для метрики «меньше лучше» отставание равно `(value / best - 1) × 100%`. Для «больше лучше» — `(1 - value / best) × 100%`. Шкала фиксирована для всех отчётов: зелёный до 5%, переход от зелёного к жёлтому до 15%, от жёлтого к красному до 30%, красный от 30%. Девять дискретных оттенков сохраняют прежнюю шкалу; цвета не растягиваются между минимумом и максимумом таблицы.

Если все значения укладываются в 5% от базы, вся группа серая. Серый означает нейтральность или недостаточное разделение; он не доказывает равенство. Текущие нативные отчёты сравнивают конечные неотрицательные значения по правилу «меньше лучше»; группа с одним значением серая. При нулевой базе ноль равен нулю, а положительное значение получает последний оттенок из-за бесконечного относительного отставания. Искусственный epsilon не добавляется.

Пороги описывают наблюдаемый размер различия. Они не являются проверками значимости, доверительными интервалами или универсальным рейтингом фреймворков. Обычные выборки нагрузки, соседние тики и фазы одной симуляции не являются независимыми прогонами.

## Какие значения можно сравнивать

- Время фреймворков: одинаковые операция, число сущностей, профиль, единицы и записанная среда. Стадия сравнивается с той же стадией других реализаций.
- Время до/после: явно заданная пара с записанной эквивалентной нагрузкой. Эксперимент, меняющий работу или исход боя, требует своей интерпретации.
- Управляемые аллокации или память: одна метрика с одной областью измерения, отдельно от времени. Байты разных видов хранилища или областей процесса не смешиваются.
- Сравнительные столбчатые графики: каждая панель использует свою описанную группу сравнения. Подписи осей определяют реализации; цвета столбцов имеют тот же смысл, что маркеры таблиц. В графиках временных рядов цвет обозначает линию, вместо одной оценки качества для меняющейся траектории.

Численность, события игры, checksum, размеры входов, число выборок, параметры и доли стадий сохраняют обычное оформление. Их величина не выражает качество производительности. Архивные результаты сохраняют дату и конфигурацию; цвет не превращает их в текущие измерения.

## Исторические исследования разброса

Сохранённые исследовательские Python-инструменты дополнительно поддерживают следующие правила; текущие нативные отчёты используют шкалу размера различия выше без вывода о разделении диапазонов.

Если доступны сводные значения независимых прогонов, база — лучшая медиана этих значений. Различия свыше 5% окрашиваются только при достаточном разделении наблюдаемых диапазонов от минимума до максимума по правилу сравнения. Пересекающиеся диапазоны, неполные данные о разбросе и малые различия остаются серыми.

Явно опубликованный интервал можно использовать вместе с записанным центральным значением. Его границы не считаются дополнительными прогонами. Эти диапазоны описывают записанный разброс и не являются доверительными интервалами.

Абсолютный порог используется только при явно записанных метрике, единицах и обосновании. Он дополняет относительное правило и не меняет напечатанный результат. Текущие нативные отчёты не используют абсолютные пороги и не читают устаревший `tools/space-battle/heatmap_policy.json`.

## Воспроизведение

[ReportColors.cs](../../tools/BenchmarkTools/ReportColors.cs) задаёт палитру и классификацию текущих .NET-отчётов. Нативные генераторы используют локальные SVG-маркеры и ту же палитру SVG-графиков без внешних изображений, CSS или сетевых вызовов.

```sh
dotnet run --project tools/BenchmarkTools -c Release -- report all
```

Команда читает сохранённые локальные данные из `artifacts/benchmarks/current` и пересоздаёт Markdown/SVG в `docs/`. Отдельные данные выбираются через `--data`, каталог публикации — через `--output`. Для смены оформления новые замеры не нужны.

[benchmark_colors.py](../../tools/benchmark_colors.py) и [оформление исследовательских отчётов](../../tools/colorize_research_reports.py) устарели и не используются текущими нативными отчётами. Поддерживаемые точки входа и границы удаления описаны в [каталоге инструментов](../../tools/README.ru.md).
